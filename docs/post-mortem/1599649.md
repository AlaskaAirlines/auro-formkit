# Post-Mortem: Distributing the Commit & Code-Review Skills via a Plugin Marketplace (AB#1599649)

**Branch:** `jbaker/reviewSkill` → `dev`
**Scope:** Package the `commit` and `code-review` Claude Code skills as a shared **plugin** (`auro`), publish them through a **plugin marketplace** repo (`AlaskaAirlines/auro-ai`), and consume that plugin in `auro-formkit` via committed `.claude/settings.json`. No component source, tests, or public API touched — this is Claude Code tooling only, so it carries no semver/npm impact.

## Executive Summary

The `commit` and `code-review` skills started life as standalone files under `auro-formkit/.claude/skills/`. That made them available in exactly one repo and impossible to version or share cleanly. This work moves them into a **plugin marketplace** so any repo on the team can consume them with change-logging handled by git.

The mechanism is Claude Code's plugin system, not npm. Claude Code does **not** scan `node_modules/` for skills, and there is no setting to add arbitrary skill search paths — so shipping skills as an npm dependency was never viable. Instead the skills now live in a dedicated git repo, `AlaskaAirlines/auro-ai`, which doubles as a **marketplace** (a catalog Claude Code reads) and the **plugin** host. A committed `.claude/settings.json` in each consuming repo points at that marketplace and enables the plugin, so anyone who trusts the repo picks up the same tools.

Because the plugin is named `auro`, its skills are namespaced: `/auro:commit` and `/auro:code-review`. Namespacing is mandatory for plugin skills (it prevents collisions between plugins) and is the one behavioral change for consumers versus the old bare `/commit` / `/code-review`.

**Bottom line:** the skills are now a single versioned source of truth in `AlaskaAirlines/auro-ai`, consumable from any repo via a committed settings block, with releases tracked through ordinary git history and tags.

## What Was Implemented

### 1. Repository layout (`AlaskaAirlines/auro-ai`)

The marketplace repo holds one catalog and one plugin:

```
auro-ai/
├── .claude-plugin/
│   └── marketplace.json          # the catalog Claude Code reads (must be at repo root)
├── plugins/
│   └── auro/                     # one plugin — its name namespaces the skills
│       ├── .claude-plugin/
│       │   └── plugin.json        # plugin manifest (name, version)
│       └── skills/
│           ├── commit/SKILL.md
│           └── code-review/SKILL.md
├── docs/project-settings-snippet.json
├── README.md
└── CHANGELOG.md
```

- **`marketplace.json`** (repo root, inside `.claude-plugin/`) declares the marketplace `name: "auro-ai"`, an `owner`, and a `plugins` array. The single entry uses an explicit relative `source: "./plugins/auro"`. (The `metadata.pluginRoot` shorthand that lets you write a bare `source` did not pass `claude plugin validate`, so the explicit path is used.)
- **`plugin.json`** declares `name: "auro"` and `version: "1.0.0"`. The plugin `name` is what namespaces the skills, so the skills resolve as `/auro:commit` and `/auro:code-review`.
- The two `SKILL.md` files are the same skills previously in `auro-formkit`, moved verbatim.

### 2. Consumption in `auro-formkit`

A committed `.claude/settings.json` makes the plugin available to everyone who opens the repo:

```json
{
  "extraKnownMarketplaces": {
    "auro-ai": { "source": { "source": "github", "repo": "AlaskaAirlines/auro-ai" } }
  },
  "enabledPlugins": { "auro@auro-ai": true }
}
```

The same snippet is kept in `auro-ai/docs/project-settings-snippet.json` so it can be dropped into any other repo. The old local copies (`.claude/skills/commit/`, `.claude/skills/code-review/`) were removed from `auro-formkit` so there is a single source of truth.

### 3. Installation without the `/plugin` panel

The interactive `/plugin` command is not available in the VS Code extension environment (`"/plugin isn't available in this environment"`). The non-interactive `claude plugin` **CLI** does the same job and was used to complete the install:

```shell
claude plugin marketplace add AlaskaAirlines/auro-ai
claude plugin install auro@auro-ai --scope project
claude plugin enable auro@auro-ai
```

`claude plugin details auro@auro-ai` then confirmed the inventory (2 skills, ~161 tokens always-on).

## How to Use

### Invoke the skills

```shell
/auro:commit <ADO ticket # | PR # | prev>     # guided Conventional Commits workflow
/auro:code-review <PR #>                       # review a GitHub PR, post comments
/auro:code-review local                        # review the current branch, output in chat
```

### Adopt the plugin in a new repo

1. Commit the settings block above (contents of `auro-ai/docs/project-settings-snippet.json`) into that repo's `.claude/settings.json`.
2. When teammates trust the folder, Claude Code prompts them to install. In environments without `/plugin`, run the one-time CLI instead:
   ```shell
   claude plugin marketplace add AlaskaAirlines/auro-ai
   claude plugin install auro@auro-ai --scope project
   ```
3. Restart the Claude Code session (or `/reload-plugins` where available) to activate.

### Release a new version

Plugin updates only reach consumers when the version changes:

1. Edit the skill(s) in `AlaskaAirlines/auro-ai`.
2. Bump `version` in **both** `plugins/auro/.claude-plugin/plugin.json` **and** the matching entry in `.claude-plugin/marketplace.json`.
3. Update `CHANGELOG.md`, commit, and tag the release (`git tag vX.Y.Z`); push.
4. Consumers pick it up via `claude plugin update auro@auro-ai` (restart to apply), or automatically if per-marketplace auto-update is enabled.

Pin a specific version when adding the marketplace:
```shell
claude plugin marketplace add https://github.com/AlaskaAirlines/auro-ai.git#v1.0.0
```

### Useful CLI commands

```shell
claude plugin list                       # show installed plugins + status
claude plugin details auro@auro-ai       # component inventory + token cost
claude plugin disable auro@auro-ai       # turn off without uninstalling
claude plugin update auro@auro-ai        # pull the latest released version
claude plugin validate .                 # validate a marketplace/plugin manifest
```

## Key Decisions

| Decision | Why |
|---|---|
| Distribute as a **plugin marketplace**, not an npm package | Claude Code doesn't scan `node_modules/` for skills and has no extra-search-path setting; the marketplace is the supported sharing mechanism and gives git-based versioning |
| Marketplace repo **is** the plugin host (`AlaskaAirlines/auro-ai`) | One repo to maintain; its git history/tags are the changelog |
| Plugin named **`auro`** → skills become `/auro:commit`, `/auro:code-review` | Plugin skills are always namespaced by plugin name; short prefix keeps invocation ergonomic |
| Explicit `source: "./plugins/auro"` in `marketplace.json` | The `metadata.pluginRoot` shorthand failed `claude plugin validate`; the explicit relative path validates cleanly |
| Consume via committed `.claude/settings.json` (`extraKnownMarketplaces` + `enabledPlugins`) at **project scope** | Anyone who trusts the repo gets the same tools with no per-person setup |
| Removed the local skills from `auro-formkit` after publishing | Avoids two sources of truth; the plugin copy is canonical |
| Installed via the `claude plugin` **CLI** | The interactive `/plugin` panel isn't available in the VS Code extension |
