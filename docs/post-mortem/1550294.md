## Executive Summary

When a guest typed a **JCB**, **China UnionPay**, or **Diner's Club** card number into the credit-card field, it displayed a generic card icon instead of that brand's own icon. This work makes the field render the correct brand icon for all three, matching how Visa, Mastercard, Amex, and Discover already appear.

## The Problem

The credit-card field only renders a brand icon for the card types defined in its detection table. **JCB** and **China UnionPay** were absent from that table, so any JCB/UnionPay number fell through to the generic `credit-card` icon. (The ticket also listed **Diner's Club**, but that brand is already defined and renders correctly on `dev` — it was filed against an older commit.)

## Root Cause

`matchInputValueToCreditCard()` in `components/input/src/base-input.js` builds a `creditCardTypes` array; each entry maps a prefix regex to a `cardIcon`. There was no entry for JCB (`35`) or China UnionPay (`62`/`81`), so both resolved to the fallback `credit-card` icon. Diner's Club (`30[0-5]|36|38` → `cc-dinersclub`) was already present. The brand icons themselves — `cc-jcb.svg` and `cc-unionpay.svg` — already shipped in `@alaskaairux/icons` (payment category); they were simply never referenced.

## The Fix

- **JCB** — new `creditCardTypes` entry: `{ name: 'JCB', regex: /^(?<num>35)\d{0}/u, cardIcon: 'cc-jcb', … }`. JCB is 16–19 digits, so it reuses the variable-length machinery (`formatMinLength: 19`, `formatLength: 23`, `4-4-4-4-3` mask) introduced for UnionPay in the sibling ticket. The `35` prefix overlaps no existing brand (Amex `34|37`, Diners `30[0-5]|36|38`).
- **China UnionPay** — delivered by AB#1551772 in the same PR (`cc-unionpay`); see that decision record for the detection/precedence/variable-length details.
- **Diner's Club** — no change; already renders `cc-dinersclub`.
- **Docs** — the user-facing brand enumeration in `docs/pages/why-input.md` and `docs/pages/css-only.md` (and their generated `demo/` mirrors) now lists JCB and China UnionPay.

## Why This Works

Icon selection is data-driven: `processCreditCard()` sets `this.inputIconName = creditCard.cardIcon`, and `renderHtmlTypeIcon()` renders `<auro-icon category="payment" name="…">`. Adding a detection entry whose `cardIcon` names an asset that already exists is all that's required. Because `35` overlaps no other brand, its placement in the last-match-wins loop doesn't affect any other card type.

## Outcome

JCB, China UnionPay, and Diner's Club numbers all display their correct brand icon. No other brand's detection or formatting changes — confirmed by the existing brand tests and a new Amex/Diners no-hijack regression.

## Learnings

- The `cc-jcb` and `cc-unionpay` SVGs already existed in `@alaskaairux/icons`; the gap was purely that the detection table never referenced them. Check the asset package before assuming a missing icon must be created.
- JCB is also variable length (16–19 digits), so it reused the machinery built for UnionPay at no extra cost — batching the two brands into one PR avoided duplicate work, while each ticket keeps its own decision record.
