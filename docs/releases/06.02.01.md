# Release Notes

This document outlines all changes since the 6.2.0 release.

Version 6.2.1 is a **patch release** focused on validation in `auro-counter-group`: a group whose child counter was invalid could be reported as valid, letting `auro-form` submit. No breaking API changes.

## Summary

Calling `validate(true)` on an `auro-counter-group`, which `auro-form` does on submit, discarded the error state the group had collected from its child counters and reset the group to valid. A form containing an invalid counter could therefore submit. The group now recomputes its validity from its children after every validation and tells `auro-form` when that changes the result. Combined child error messages also render as plain text instead of `[object Object]`.

- `auro-form` no longer submits while an `auro-counter-group` has an invalid child counter.
- The group's combined error message renders as readable text, with each child's message separated by `. `.
- The counter group's fullscreen footer buttons now render and respond on the customize demo page.

All changes are backward compatible. Consumers should update without migration work.

## Bug Fixes

_Note: Bug fixes do not require migration steps. Updating to this version is all that is necessary to implement these changes._

### AURO-COUNTER

- **Preserve counter-group child errors through forced validation** — [AB#1642340](https://itsals.visualstudio.com/5e9f12eb-f830-406f-bee9-be25938f7aaa/_workitems/edit/1642340)

    The shared validator in `form-validation` treats an object-valued `value` as having no value, and `auro-counter-group`'s value is an object holding each child counter's value. So `validate(true)` always reset an otherwise error-free group straight to `valid`, and nothing recomputed its state from the children afterward. `validate()` now recomputes validity from the children right after the shared validator runs. When that changes the result, it dispatches `auroFormElement-validated` again, so `auro-form`'s submit path sees the corrected state. The recomputation runs on every `validate()` call, not just forced ones. Limiting it to forced calls broke `auro-form`'s disabling of the submit button on initial load. Combined error messages are now joined into a plain string instead of an array of Lit templates, which fixes a separate `[object Object]` rendering bug on the same path. A fallback that could show a previous error's message after the group moved to a new error with no message of its own was also removed.

## Test Coverage

- **counter:** WTR regression tests covering both call orderings, recovery after the error is fixed, the message separator, the stale-message fix, and direct assertions on the re-dispatched event. A Chromatic story pins the dropdown variant. The `bib.fullscreen.footer` test now opens the bib and asserts the footer content is moved into the bib template's `footer` slot (and into `#footerContainer` at small viewports). Previously it only checked that the node existed.
- **framework apps:** a Playwright test exercises a real form submit with an invalid counter group in both the React and Svelte apps.
